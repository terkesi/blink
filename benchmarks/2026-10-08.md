# Retrieval evaluation, 2026-10-08

Blink did not qualify for team release. On a fresh held-out comparison, the retained candidate completed 6 of 11 positive questions and the Reference CLI completed 8. Blink returned source on 6 of 12 negative questions, the Reference CLI on 12. Two Blink trials ended with provider refusals. Blink's median search took 3.06 seconds with 18 requests; the Reference CLI took 18.44 seconds with 44 requests.

The retained change adds up to two follow-up requests that judge helper definitions called by accepted source. It raised calibration from 10/12 to 11/12 in two runs, raised the consumed 45-question set from 15/30 to 18/30, and raised the fresh held-out result from 5/11 to 6/11, with unchanged negative-source and error trials in each comparison. It costs two extra requests at most per search.

## What changed

Main's shared-identifier follow-up plan stays byte for byte. After it finishes, and only while a full attempt timeout remains, up to two more requests judge windows that declare a function, class or type called by accepted source, with the calling window as related source. Keyword and parenthesis patterns find declarations and calls. These requests skip windows that were already planned or accepted, so they can add matches but cannot retract them. They also skip callers that the shared-identifier pass rejected. A deadline during these requests keeps the shared-identifier results.

Default fresh work rises from 16 requests and 512 KiB to 18 requests and 608 KiB. All work, including retries, rises from 18 attempts and 640 KiB to 20 attempts and 736 KiB. The deadline, concurrency, output limits, instructions and thorough mode are unchanged. Evaluation receipts now record every judgment with the donor that accompanied it.

## Diagnosis that led to the change

The receipts for the two remaining calibration misses kept only final probabilities, so the first diagnosis replayed the planner on them. An exact replay later used the recorded initial-pass judgments and corrected that approximation. The Timeout window that `build_request` calls was never planned by the shared-identifier pass. The two cookie windows were planned in its seventh and eighth jobs, with the calling `_merge_cookies` window as donor, and scored 0.45 and 0.01. One miss was an admission gap, the other a judgment failure with the right context.

Two measurements shaped the design. Identical request bodies returned identical probabilities, and the two baseline runs had identical request bytes and judgments on all 24 questions, so live runs are deterministic for a fixed build. Batch composition changes scores. The same window and donor scored 0.71 in one batch and 0.28 in another. Single-candidate requests scored three of four helper windows higher than eight-candidate batches with the same donor.

## Fresh held-out comparison

The held-out split of the newer dataset has 24 questions across the same two public source trees as calibration. One positive case, `next-httpx-hel-05`, was prospectively excluded because a fragment of it was exposed during an earlier metadata search, leaving 11 positive and 12 negative questions. The protocol, executables, corpus hash and gates were frozen before any held-out retrieval. The candidate and the Reference CLI ran in one invocation with alternating order per question; the two other Blink versions ran separately on the same 23 questions. Each question ran once.

| Version | Complete positives | Source on negatives | Error trials | Median requests | Median encoded bytes per search | Median wall time |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Production baseline, rebuilt `fa77862` | 5/11 | 6/12 | 1/23 | 8 | 202,040 | 1.31 s |
| Main `1b44c52` | 5/11 | 6/12 | 2/23 | 16 | 461,399 | 2.37 s |
| Candidate `fcd2119` | 6/11 | 6/12 | 2/23 | 18 | 487,179 | 3.06 s |
| Reference CLI 0.8.0 | 8/11 | 12/12 | 0/23 | 44 | 1,563,191 | 18.44 s |

All Blink error trials were provider refusals. The candidate's two refusal trials are the same questions as main's, and both still returned every required span; the primary metric gives error trials no credit. The Reference CLI completed 7 of 11 within its first eight records and 8 of 11 across all returned records; the gate uses all returned records for both tools. Its trials ran through the TypeSafe provider with 1,000 allowed requests, 32 concurrent requests, a 32 KiB output cap and caching disabled. Blink used `gpt-6-luna` through the Decisions API with its default limits. Request counts and bytes therefore do not compare price.

Over the 21 questions where neither tool erred, Blink finished a median 15.2 seconds sooner, with a range of 8.0 to 24.8 seconds. These are single runs of different questions in one quality run, taken while the machine had a load average near 9 on 16 cores, so they are descriptive. The protocol defers repeated timing until quality qualifies.

| Release gate | Result |

Calibration overstated fresh performance. Main completed 10 of 12 calibration questions and 5 of 11 fresh ones. This held-out split is now consumed. Further gains need a new, independently authored split before any release claim.

## Next work

Provider refusals cost Blink two fresh answers that contained every required span, and they also appear on 3 of 45 consumed questions. Re-asking a refused window in a different batch is the next reliability experiment, since composition changes judgments. The fresh misses that were not refusals were partial multi-span answers. A new held-out split is required before the next release claim.
