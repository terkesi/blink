# Retrieval evaluation, 2026-10-07

No candidate in this evaluation cycle qualified for release. Region previews improved a separate calibration set from 4/12 to 7/12 complete positive answers. Related-source follow-up with bounded retries at `b435d94` then reached 10/12 in two runs and is retained for further development. The earlier comparisons and rejected experiments remain below.

## Fresh public-source comparison

This independently authored dataset contains 30 positive and 15 negative questions across three public source trees, with 62 required spans. Candidate and dataset hashes were frozen before results were inspected. Each question ran once per version. Both tools had a 32 KiB serialized output limit, with different output formats. The table counts all returned source records within that limit.

| Version | Complete positives | Source on negatives | Errors | Median requests | Median encoded bytes per search |
| --- | ---: | ---: | ---: | ---: | ---: |
| Production baseline, `2560970` | 5/30 | 0/15 | 3/45 | 8 | 195,259 |
| Reference CLI, `external 0.8.0` | 24/30 | 12/15 | 0/45 | 59 | 1,876,228 |
| Byte packing, `ab98278` | 6/30 | 2/15 | 0/45 | 8 | 260,527 |

The reference returned all required source within its first eight records for 20/30 questions, compared with 24/30 across all returned records. Its output was truncated in 16/45 trials. Every Blink trial reported incomplete exploration. The comparison driver marked the reference complete based on its exit status and output markers. That is not independent proof that every source region was inspected.

The runs used different providers and work limits. Blink default allowed eight attempts, 256 KiB of encoded requests, four concurrent requests, and a 15-second deadline. The reference allowed 1,000 requests and 32 concurrent requests, with caching disabled and a 90-second process timeout. Actual reference requests ranged from 25 to 122. This comparison measures the configured tools, not their implementation languages.

The byte-packing candidate was rejected. It returned source on two additional negative questions and remained below the predeclared completeness target. Its earlier synthetic calibration improved from 8/16 complete positives to 10/16 in two runs. That gain did not establish performance on real source.

## Retry headroom

Late transient failures could not retry after fresh work consumed the request allowance. Candidate `b435d94` retains the general-identifier relationship strategy from `b00c8bc` and reserves extra capacity only for retries. Fresh work remains bounded by sixteen requests and 512 KiB; all actual work, including retries, is bounded by eighteen requests and 640 KiB. The deadline remains fifteen seconds. One ledger counts every attempt and body.

| Version | Complete positives | Source on negatives | Errors | Median requests | Median encoded bytes per search |
| --- | ---: | ---: | ---: | ---: | ---: |
| Retry headroom, `b435d94`, run 1 | 10/12 | 5/12 | 0/24 | 16 | 493,829.5 |
| Retry headroom, `b435d94`, run 2 | 10/12 | 5/12 | 0/24 | 16 | 493,829.5 |

Both runs dispatched no retries. Their quality results therefore cannot be attributed to recovered requests. Failure-injection tests separately establish recovery: a late source batch retries with identical bytes, a routing retry preserves the routing barrier, and exhausted headroom leaves an error visible. Pending failures survive cancellation of an in-flight retry. Successful request bodies and source targets match the parent in a controlled sixteen-request run. Thorough-mode limits remain unchanged.

Retain this version for development: it adds three complete calibration answers over the retained region-preview version, with unchanged negative-source results and zero errors in both runs. It still misses the fresh-validation and release targets. A separate 130-line cleanup removed unused context support from the callable control and passed local tests and review, but was not measured live before this selection. It remains off main; lower LOC alone does not establish that it preserves the leading result.

## Decision and unfinished work

The predeclared acceptance target remains at least 90% complete positives, at least reference completeness, no additional source on negative questions versus production, and zero execution or integrity errors. Team release also requires a strict completeness win over the reference. This cycle did not reach either target.

The region-preview and related-source designs produced the repeated calibration gains above. Further work must improve the remaining misses and pass fresh comparison before team release.
